# IDEAL — Microsoft Store distribution

IDEAL ships a direct Windows NSIS installer from GitHub Releases. The free GitHub installer is not Authenticode-signed, so Windows SmartScreen may still show an unknown-publisher or reputation warning.

The optional Microsoft Store route is separate:

1. Register a Microsoft Store developer account and complete Microsoft's identity verification.
2. Reserve the product name **IDEAL** in Partner Center.
3. Open Product identity and copy the exact Package/Identity Name, Publisher, and Publisher display name.
4. After this branch is merged into `main`, open GitHub Actions and run **Build IDEAL Microsoft Store package** manually. Enter those three public package-identity values in the workflow inputs. They are not secrets.
5. Download the `IDEAL-Microsoft-Store-AppX` artifact and submit the `.appx` package in Partner Center.
6. Complete the Store listing, privacy disclosures, age rating, screenshots, and certification process.

Microsoft signs an accepted Store submission. Building an AppX file does not itself mean Microsoft has approved or signed IDEAL. The app is not publicly listed until certification succeeds.

## Technical behavior

- The existing NSIS `.exe` release remains the direct-download edition and continues using GitHub/electron-updater.
- The AppX package is generated by a separate manually triggered workflow; it is not automatically published to customers.
- Store-installed packages use Microsoft Store for updates. IDEAL disables electron-updater when `process.windowsStore` is true.
- Electron's local Express server and SQLite database remain inside the packaged app's per-user data directory. No production database is used during package creation or tests.
- No PFX, signing certificate, password, or signing secret is stored in the repository.
- The package identity values must match Partner Center exactly. The final Store certification decision belongs to Microsoft.

## SmartScreen

Do not disable SmartScreen or Windows Defender and do not distribute a self-signed root certificate. For direct public downloads, a trusted Authenticode certificate is normally paid. Microsoft Store distribution is the free route for a Microsoft-verified package signature.
